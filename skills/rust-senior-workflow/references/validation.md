# Rust validation decisions

Use repository CI and documented commands first. Select checks from the changed behavior and supported configurations; these are conditional checks, not a requirement to run every tool on every task. Replace example package names, versions, features, and target triples with values from the project.

| Change or contract | Validation decision |
| --- | --- |
| Local implementation | Start with `cargo test -p affected-package` and the relevant test filter. Run formatting and Clippy under the repository's lint policy. Broaden to affected consumers; use workspace checks for shared dependencies, public interfaces, or cross-crate changes. |
| Minimum supported Rust version (MSRV) | Read `package.rust-version`, including workspace inheritance, and CI's supported-version policy. When syntax, standard-library APIs, dependencies, edition, or Cargo configuration changes, run the applicable package check/tests with the declared minimum toolchain, e.g. `cargo +1.70.0 check -p affected-package --lib`. A current-toolchain pass does not establish MSRV support. Do not silently raise MSRV or install another toolchain when the environment prevents it; report the gap. |
| Optional dependencies or `cfg(feature)` | Test the default configuration and each affected supported configuration independently, e.g. `cargo test -p affected-package --no-default-features` and `cargo test -p affected-package --no-default-features --features optional-feature`. Use `--all-features` only when that combination is supported. Workspace feature unification can hide missing feature declarations, so check an affected library on its own when needed. |
| OS, architecture, `no_std`, or target-specific dependencies | Run `cargo check -p affected-package --target supported-triple` with the relevant feature selection. Run tests on the target when a runner is available. A cross-check verifies compilation, not runtime behavior. Report missing standard libraries, linkers, native libraries, or runners. |
| Public API or documentation | Check affected downstream callers and documentation examples. Run applicable doctests and `cargo doc -p affected-package --no-deps`; use the repository's rustdoc warning policy, or `RUSTDOCFLAGS="-D warnings"` for a strict documentation check. Review compatibility beyond compilation, including types, trait bounds, error behavior, and feature availability. |
| Dependency or lockfile changes | Inspect the resolution and manifest/lockfile diff for intended versions, features, MSRV, and target effects. Preserve the repository's lockfile policy. Use `--locked` when validating against an existing committed lockfile that should remain unchanged; after an intended dependency update, validate the updated lockfile. Do not run broad dependency updates to fix an unrelated check. |

Use `rustc -Vv`, `cargo -V`, and `rustup show active-toolchain` as needed to identify the actual environment. A toolchain pin may be newer than the minimum supported version. A feature or target matrix need only cover the supported combinations relevant to the change.

For unsafe changes, add tests at the affected invariant boundary. Use Miri when it supports the code and is available; a passing run covers the executions tested and is not a proof of soundness. Use fuzzing or concurrency model checking when the changed parser or synchronization algorithm warrants it and the project supports those tools. Report unavailable checks instead of substituting a clean Clippy run for runtime evidence.

For each failure, record the diagnostic and configuration. If attribution matters, reproduce against the pinned base in a separate checkout without disturbing the user's working tree. Preserve the same toolchain and dependency selection. Classify a failure as pre-existing only with evidence; otherwise leave its attribution unresolved. Do not clean up unrelated warnings merely to satisfy a new strict flag.

Authoritative references: [MSRV](https://doc.rust-lang.org/cargo/reference/rust-version.html), [features](https://doc.rust-lang.org/cargo/reference/features.html), [Cargo test](https://doc.rust-lang.org/cargo/commands/cargo-test.html), [SemVer compatibility](https://doc.rust-lang.org/cargo/reference/semver.html), [Miri limitations](https://github.com/rust-lang/miri#readme).
